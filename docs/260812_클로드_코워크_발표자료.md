# AI 잘 쓰는 법보다, 먼저 알아야 할 것

AI가 **뭘 잘하고 뭘 못 하는지**는 작동 원리에서 그대로 나온다.
**원리를 모르면, 뒤에 나올 시연은 그냥 마술쇼로 보일 뿐.**

## 인공지능의 본질은 분류와 예측

- AI가 하는 일은 결국 둘뿐. **분류(classification)와 예측(prediction)**
- **배운 적 없는 건 분류하지 못한다.** 데이터가 많고 다양할수록 정확해진다.
- 그래서 **사람이 일일이 가르쳐야 했다.** 이미지 박스 하나에 200원씩 주고 표시하던 **데이터 라벨링**
- 그렇게 쌓은 결과 -> 흉부 엑스레이를 **의사보다 AI가 먼저 읽어낸다.**

> 오늘 첫 시연(D1)이 정확히 이것. **파일 이름이 아니라 내용을 읽고 분류한다.**
> **AI가 똑똑해서가 아니라, 분류가 원래 AI가 제일 잘하는 일이라서 되는 것.**

## AI는 도대체 어떻게 결과물을 만들어낼까?

**GPT = Generative Pre-trained Transformer**

| 단어 | 뜻 | 실무적 함의 |
|---|---|---|
| **Generative** | 생성형 | 사람처럼 새로운 텍스트나 결과물을 만들어냄 |
| **Pre-trained** | 미리 학습해 둠 | 실시간 학습이 아님 → **최신 정보를 모르는 구조적 한계** |
| **Transformer** | 2017년 구글 논문 *Attention Is All You Need* 의 알고리즘 | **다음 단어를 확률로 예측**해 하나씩 생성 |

- 예: `Data Visualization import user2 Generator` 다음에 올 단어 → `and` 36% / `,` 22% / `or` 14% 중 선택
- **정답을 찾아오는 게 아니다. 그럴듯한 다음 단어를 계속 고르는 것.** 모든 LLM 답변이 이 과정을 거친다.
- https://poloclub.github.io/transformer-explainer/

> **AI는 검색엔진이 아니라 문장 완성기**
> 그래서 "무엇을 보여줬느냐"가 결과를 바꾼다.

## 그래서 할루시네이션은 못 없앤다

**할루시네이션(환각)** — 사실과 무관하거나 맥락이 안 맞는 정보를 **사실인 것처럼** 생성하는 현상

- 확률로 다음 단어를 고르는 구조인 이상 **제거 불가능.** 줄일 수 있을 뿐이다.
- 대표 사례: **"세종대왕의 맥북프로 던짐 사건을 알려줘"** → 아주 그럴듯한 거짓 답변
  **한국인은 바로 웃는다. 그 분야를 모르면 못 웃는다.**
- 실제 사례: 선행연구 찾아달라고 했더니 **세상에 없는 논문**을 만들어냄.
- 출처 표시·검색 기반(RAG)으로 많이 완화됐지만 **없어진 게 아니다.**

> **할루시네이션은 AI의 버그가 아니라 사양(spec)이다.**
> 고쳐지길 기다릴 게 아니라, **알아볼 수 있는 사람이 검토하는 것**이 유일한 대책.

## 코워크에서는 이 위험이 더 커진다

**채팅** — 답이 눈앞에 뜬다. 읽다가 이상하면 알아챈다.

**코워크** — 결과가 **파일로 조용히 저장된다.** 한 번도 안 열어보고 제출할 수 있다.

> 코워크의 위험은 **틀리는 게 아니라**,
> **그럴듯한 파일이 이미 완성돼 있다는 것.**

## 보안 — 클라우드 AI의 구조적 전제

- 클라우드 AI는 **입력이 서버로 가는 구조.** 이건 못 피한다.
  근본 해결책은 온디바이스(로컬) 모델뿐인데, 아직 성능 격차가 크다.
- 각 기업은 "학습에 쓰지 않는다"고 밝히고, 설정으로 끌 수도 있다. 다만 **전송 자체는 일어난다.**
- **비즈니스/엔터프라이즈 계정**은 관리·감사·보관 정책이 개인 계정과 다르다.

#### 코워크는 여기서 한 발 더 나간다

**업로드 버튼을 안 눌러도 읽는다.** 연결한 폴더 안이면 전부.

- 회사 R&D 원천자료 · 개인정보 · 미공개 계약 조건 → **사내 정책 확인이 먼저**
- 필요하면 이름·금액·식별자를 **마스킹한 사본**으로 작업
- 개인 Pro 계정으로 회사 자료를 다루기 전에 반드시 승인 절차

> **챗은 내가 올린 것만 본다. 코워크는 폴더에 있는 것을 본다.**

## 그래서 진짜 경쟁력은 "전문성"

- "AI가 일자리를 뺏는 게 아니라, **AI를 잘 쓰는 사람이 뺏는다**"
- **AI 활용은 진입 장벽이 거의 없음.** 누구나 3일이면 OK
  **진입 장벽이 사라진 곳에, 경쟁력-차별화 없다!**
- 남는 건 **도메인 지식과 판단력** -> 일하면서 쌓은 **경험의 깊이**

> AI 로 이미지 생성할 때, 좋은 결과물을 만드는 사람은, AI를 잘 쓰는 사람이 아니라 구도·조명·색감 등의 지식을 가진, **사진이나 이미지를 잘 아는 사람**
> **경비 정산 규정을 아는 사람이 경비 정산을 잘 한다.**

## 세 가지를 한 표로

| | **웹 브라우저 채팅** | **Claude for Excel / PowerPoint** | **Claude 코워크** |
|---|---|---|---|
| **어디서 쓰나** | 브라우저 claude.ai | 엑셀·파워포인트 **안의 사이드바**(추가 기능) | 데스크톱 앱 (웹·모바일도 가능) |
| **작업 대상** | 대화창에 **업로드한** 파일 | 지금 **열려 있는** 그 문서 | 연결한 **폴더 전체** |
| **결과물이 나오는 곳** | 채팅창 안 → 복사·다운로드해서 옮김 | **그 문서에 바로** (셀·수식·차트·슬라이드) | 내 폴더에 **새 파일로** 생성 |
| **파일을 새로 만드나** | 다운로드만 가능 | **못 만든다.** 열려 있는 파일만 읽고 씀 | 만들고, 옮기고, 이름도 바꿈 |
| **여러 파일** | 하나씩 업로드 | 열려 있는 Excel·PPT·Word·Outlook 사이는 오감 | 폴더 안 수십 개를 한 번에 |
| **역할** | 답을 **알려주는** 도구 | 이 문서를 **같이 고쳐주는** 도구 | 일을 **대신 해주는** 도구 |
| **플랜** | 무료도 가능 | 유료 (Pro/Max/Team/Enterprise) | 유료 (Pro/Max/Team/Enterprise) |

**세 줄만 기억하면 된다.** 어디 있는 걸 건드리나 / 결과가 어디에 놓이나 / 알려주나 해주나.

## 언제 뭘 켜나 — 판단 기준 하나

| 지금 하려는 일이... | 켤 것 |
|---|---|
| 답·설명·초안만 필요하다. 파일이 안 나와도 된다 | **웹 채팅** |
| 지금 보고 있는 **그 엑셀 한 개 / 그 장표 한 벌**을 고치는 일이다 | **Excel / PowerPoint 애드인** |
| **여러 파일을 읽어서** 여러 결과물을 **내 폴더에** 만들어야 한다 | **코워크** |
| 정해진 시간에 **내가 없어도** 돌아야 한다 | **코워크(스케줄)** |

- 코워크는 채팅보다 **사용량을 훨씬 많이 먹는다.** 아무 일에나 켜는 도구가 아니다.
- 채팅의 메모리는 코워크로 안 넘어온다(같은 프로젝트 안이면 예외).

> **망치가 좋다고 나사까지 망치로 박지는 않는다.**

## 새로 배울 개념은 네 개가 전부

| 개념 | 비유 | 한 줄 정의 | 언제 쓰나 |

## 이 셋만 지키면, 사고가 나도 폴더 안에서 끝난다

**01 · 전용 폴더에서만 쓴다**

## 기다리는 동안 · 결과물이 왜 죄다 `.md` 인가

**마크다운(Markdown)** — 기호 몇 개로 서식을 표현하는 **텍스트 작성 규칙.** 2004년에 만들어졌다.

```
# 제목          ## 소제목          ### 작은 제목
**굵게**    *기울임*    `코드`    ~~취소선~~
- 글머리 목록        1. 번호 목록        - [ ] 체크박스
> 인용문
[링크 이름](https://claude.ai)
| 이름 | 금액 |
|---|---|
| 김철수 | 12,000 |
```

- **배울 게 없다.** 위에 있는 게 실무에서 쓰는 것의 90%다. 나머지는 검색하면 나온다.
- 지금 만들어지고 있는 `정리내역.md`, 뒤에 나올 `주간요약.md` `사전검토_메모.md` 전부 이 문법이다.

## 마크다운의 장점 · 그리고 어디서 보나

- **아무 데서나 열린다.** 특수 프로그램이 필요 없다. 메모장으로 열린다. **20년 뒤에도 열린다.**
- **서식이 깨지지 않는다.** 깨질 서식 자체가 없기 때문이다.
- **AI가 가장 잘 다루는 형식.** 사람도 읽고 기계도 읽는다. 그래서 코워크의 기본 출력이다.
- **고치기 쉽다.** 한 줄만 바꿔서 다시 시킬 수 있다. 무엇이 바뀌었는지도 눈에 보인다.

| 도구 | 성격 |
|---|---|

| **Notion · GitHub · 클로드 채팅창** | 그냥 붙여넣으면 알아서 서식으로 보여줌 |
| **메모장 · 아무 편집기** | 서식은 안 보여도 **내용은 100% 읽힌다** |

> **최종본이 워드·PDF여야 한다면** — 마크다운으로 작업하고 마지막에 한 번만 변환한다.

## D6 · 시키지 않아도 알아서 처리하려면

**예정됨** — 사이드바 `예정됨` → 새 작업 - 수동으로 설정  → 이름·작업 내용 → 저장 폴더 → 빈도 **매일 오전 7시** → 저장 → **지금 실행**으로 즉석 테스트

```
기능성 소재·소부장 분야의 지난 24시간 주요 뉴스 3건을 정리해 줘.
각 뉴스마다: 제목과 출처(매체명), 발행일 / 3줄 요약 /
우리 연구소 업무 관점의 시사점 1줄 (해당 없으면 "직접 관련 없음") / 원문 링크
규제·정부 정책 소식은 우선순위를 높게. 확인되지 않은 내용은 넣지 마.
뉴스가 3건이 안 되면 있는 만큼만. 파일명은 `YYYYMMDD_업계브리핑.md`
실행하기 전에 어떻게 할지 계획만 먼저 알려줘.
```

> "매일 아침 뉴스 3건"은 대단해 보이지 않는다. 이걸 **매주 월요일 미결 액션아이템 리마인드**,
> **매월 1일 예산 집행률 점검**으로 바꿔보세요. **까먹어서 늦는 일이 사라진다.**

## 여전히 안 되는 것, 조심할 것

**01 · 검토 시간은 줄지 않는다**
오히려 늘 수도 있다. 줄어드는 건 **만드는 시간**이지 **보는 시간**이 아니다.

**02 · 틀린 결과가 파일로 조용히 저장된다**
채팅은 눈앞에서 읽고 넘어간다. 파일은 **안 읽고도 제출된다.**

**03 · 사용량을 많이 먹는다**
채팅보다 훨씬 빨리 한도에 닿는다. 아무 일에나 켜지 마세요.

**04 · 완전 자동화는 목표가 아니다**
사람이 판단할 지점은 남겨두세요. **수동 승인으로 두는 이유가 그것.**
