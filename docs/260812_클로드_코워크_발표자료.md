## 인공지능의 본질은 분류와 예측입니다

- 인공지능이 하는 일은 결국 **분류(classification)와 예측(prediction)** 입니다.
- **학습 데이터에 없는 것은 분류하지 못합니다.** 데이터가 많고 다양할수록 정확해집니다.
- 그래서 **데이터 라벨링**이 필수였습니다. 과거에는 이미지의 박스 하나에 200원씩 주고 사람이 일일이 표시했습니다.
- 지금은 흉부 엑스레이에서 **의사보다 AI가 먼저 병명을 읽어내는** 수준까지 왔습니다.

> 오늘 볼 첫 시연(D1)이 정확히 이것입니다. **파일 이름이 아니라 내용을 읽고 분류**합니다.
> 사람이 "이건 회의록, 이건 예산 자료"라고 알려주지 않아도 됩니다.

## 그런데 글은 어떻게 만들어낼까 — 트랜스포머

**GPT = Generative Pre-trained Transformer**

| 단어 | 뜻 | 실무적 함의 |
|---|---|---|
| **Pre-trained** | 미리 학습해 둠 | 실시간 학습이 아님 → **최신 정보를 모르는 구조적 한계** |
| **Transformer** | 2017년 구글 논문 *Attention Is All You Need* 의 알고리즘 | **다음 단어를 확률로 예측**해 하나씩 생성 |

- 예: `Data Visualization import user2 Generator` 다음에 올 단어 → `and` 36% / `,` 22% / `or` 14% 중 선택
- **정답을 찾아오는 게 아니라, 그럴듯한 다음 단어를 계속 고르는 것**입니다. 모든 LLM 답변이 이 과정을 거칩니다.

## 그래서 할루시네이션은 못 없앱니다

**할루시네이션(환각)** — 사실과 무관하거나 맥락이 안 맞는 정보를 **사실인 것처럼** 생성하는 현상

- 확률로 다음 단어를 고르는 구조인 이상 **근본적으로 제거 불가능**합니다. 줄이려고 노력할 뿐입니다.
- 대표 사례: **"세종대왕의 맥북프로 던짐 사건을 알려줘"** → 아주 그럴듯한 거짓 답변
  한국인은 바로 알아채지만, 그 분야를 모르면 못 알아챕니다.
- 실제 사례: 논문 선행연구를 찾아달라고 했더니 **존재하지 않는 논문**을 있는 것처럼 만들어냄.
- 최근에는 출처 표시·검색 기반(RAG) 기능으로 많이 완화됐지만, **없어진 게 아닙니다.**

## 코워크에서는 이 위험이 더 커집니다

## 보안 — 클라우드 AI의 구조적 전제

- 클라우드 기반 AI는 **입력이 서버로 전송되는 구조**입니다. 이건 피할 수 없습니다.
  근본 해결책은 온디바이스(로컬) 모델뿐인데, 아직 성능 격차가 큽니다.
- 각 기업은 "학습에 쓰지 않는다"고 밝히고 있고, 설정으로 끌 수도 있습니다. 다만 **전송 자체는 일어납니다.**
- **비즈니스/엔터프라이즈 계정**은 관리·감사·데이터 보관 정책이 개인 계정과 다릅니다.

#### 코워크는 여기서 한 발 더 나갑니다

**내 컴퓨터의 로컬 파일을 읽어서 보냅니다.** 업로드 버튼을 누르지 않아도, 연결한 폴더 안이면 읽습니다.

- 회사 R&D 원천자료 · 개인정보 · 미공개 계약 조건 → **사내 정책 확인이 먼저**
- 필요하면 이름·금액·식별자를 **마스킹한 사본**으로 작업
- 개인 Pro 계정으로 회사 자료를 다루기 전에 반드시 승인 절차

## 그래서 진짜 경쟁력은 "전문성"입니다

- "AI가 일자리를 뺏는 게 아니라, **AI를 잘 쓰는 사람이 뺏는다**" — 여기까진 동의합니다.
- 그런데 **AI 활용은 진입 장벽이 거의 없습니다.** 누구나 3일이면 배웁니다.
  **진입 장벽이 사라진 곳에 경쟁력은 존재하지 않습니다.**
- 남는 건 **도메인 지식과 판단력**입니다. 여기서 전문직이란 의사·변호사가 아니라,
  일하면서 쌓은 **경험의 깊이**를 말합니다.

> 이미지 생성할 때 구도·조명·색감을 구체적으로 말하는 사람은 AI를 잘 쓰는 게 아니라
> **이미지를 잘 아는 사람**입니다. 코워크도 같습니다.
> **경비 정산 규정을 아는 사람이 경비 정산을 잘 맡깁니다.**

## 세 가지를 한 표로

| | **웹 브라우저 채팅** | **Claude for Excel / PowerPoint** | **Claude 코워크** |
|---|---|---|---|
| **어디서 쓰나** | 브라우저 claude.ai | 엑셀·파워포인트 **안의 사이드바**(추가 기능) | 데스크톱 앱 (웹·모바일도 가능) |

| **파일을 새로 만드나** | 다운로드는 가능 | **못 만듭니다.** 열려 있는 파일만 읽고 씀 | 만들고, 옮기고, 이름도 바꿈 |

## 언제 뭘 켜나 — 판단 기준 하나

| 지금 하려는 일이... | 켤 것 |
|---|---|
| 답·설명·초안만 필요하다. 파일이 안 나와도 된다 | **웹 채팅** |
| 지금 보고 있는 **그 엑셀 한 개 / 그 장표 한 벌**을 고치는 일이다 | **Excel / PowerPoint 애드인** |
| **여러 파일을 읽어서** 여러 결과물을 **내 폴더에** 만들어야 한다 | **코워크** |
| 정해진 시간에 **내가 없어도** 돌아야 한다 | **코워크(스케줄)** |

- 코워크는 채팅보다 **사용량(usage)을 훨씬 많이 씁니다.** 아무 일에나 켜는 도구가 아닙니다.
- 채팅의 메모리는 코워크로 넘어오지 않습니다(같은 프로젝트 안이면 예외).

## 새로 배울 개념은 네 개뿐입니다
