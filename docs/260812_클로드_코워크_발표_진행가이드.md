## 0. 이 발표의 설계 의도

지난 4월 교육의 결론은 **"툴이 아니라 태도와 전문성"** 이었습니다. 이 발표는 그 결론을 부정하지 않고 이어받습니다.

- 4월 교육: AI가 **답을 잘 주게** 만드는 법 → 챗 중심
- 이번 발표: AI가 **일을 대신 하게** 만드는 법 → 코워크 중심
- 연결 고리: **"내 업무를 가장 잘 아는 사람만이 무엇을 맡길지 정할 수 있다"**

그래서 앞 30분은 개념·태도, 뒤 50분은 손으로 만지는 시연입니다. 개념 파트를 건너뛰면 "신기한 툴 봤다"로 끝나고 다음 주에 아무도 안 씁니다.

## 3. 파트별 진행 스크립트

### 오프닝 (5분) — 말보다 먼저 보여주기

설명 없이 바로 D1을 30초짜리로 한 번 돌립니다. 폴더가 정리되는 걸 보여준 뒤에 이렇게 시작하세요.

> "지금 보신 게 오늘 내용 전부입니다. 여러분이 지금 쓰고 있는 챗은 **'이렇게 정리하시면 좋겠어요'** 라고 알려줍니다. 방법은 알려주는데 정리는 결국 제가 하죠. 오늘 볼 도구는 **진짜로 정리해서 돌려줍니다.** 그 차이 하나 때문에 매주 하던 일이 한마디로 끝납니다."

**오늘의 약속 3가지** (슬라이드로 띄우고 읽기)

1. 새로 배울 개념은 딱 4개입니다 — 폴더 / 프로젝트 / 스킬 / 스케줄
2. 코딩은 한 줄도 안 합니다
3. 나가실 때 **내 업무 중 코워크에 맡길 것 1개**를 정해서 나가십니다

### Part 1 (10분) — 4월 교육에서 안 변한 것 3가지

도구가 바뀌어도 유지되는 원칙입니다. 여기서 청중의 "AI 만능론"과 "AI 무용론"을 동시에 눌러야 시연이 제대로 읽힙니다.

**① 잘 쓰는 사람은 프롬프트 고수가 아니라 그 분야를 아는 사람**

> "이미지 생성할 때 구도·조명·색감을 구체적으로 말하는 사람은 AI를 잘 쓰는 게 아니라 **이미지를 잘 아는 사람**입니다. 코워크도 똑같습니다. 경비 정산 규정을 아는 사람이 경비 정산을 잘 맡깁니다. 규정을 모르면 AI가 만들어 온 표가 맞는지 틀린지도 모릅니다."

**② 할루시네이션은 못 없앱니다 — 그래서 검토가 일입니다**

- 세종대왕 맥북프로 사건, 존재하지 않는 선행연구 논문 사례를 다시 언급
- 4월 교육의 딥리서치 사례: **AI 37분 / 사람 3일**, 그러나 **레퍼런스 검증에 하루**
- 코워크로 넘어오면 이 원칙이 더 중요해집니다. **답이 아니라 파일이 나오기 때문에 안 읽고 넘어가기 쉽습니다.**

> "코워크의 위험은 틀리는 게 아니라, **그럴듯한 파일이 조용히 만들어져 있다는 것**입니다."

**③ AI에 집착하지 말고 문제에 집중**

- 10년 전 빅데이터 열풍의 실패 패턴: "우리도 데이터 많으니 뭐라도 해보자" → 예쁘지만 아무도 안 쓰는 결과물
- 순서는 항상: **우리 문제가 뭔가 → 해결하면 뭐가 좋은가 → 그럼 뭐가 필요한가**

> "오늘 시연을 보시면서 '와 신기하다'가 아니라 **'이거 내가 매주 하는 그 일이네'** 라는 생각이 드는 순간을 메모하세요. 그게 여러분의 첫 번째 코워크 과제입니다."

**보너스 슬라이드 (시간 있으면)**: 4월 교육의 "답변 퀄리티는 질문 차이보다 모델 차이가 크다" → 코워크에서는 **"모델 차이보다 맥락(파일·폴더) 차이가 크다"** 로 한 단계 더 갑니다. 이게 Part 2로 넘어가는 다리입니다.

### Part 2 (10분) — 채팅 vs 코워크, 결정적 차이 3가지

영상의 핵심 프레임입니다. 슬라이드 한 장에 표로 띄우고 말로 풀어주세요.

| | Claude 채팅 (지금 쓰시는 것) | Claude 코워크 |
|---|---|---|
| **파일을 주는 방법** | 대화창에 하나씩 **업로드** | 내 컴퓨터의 **폴더를 연결** |
| **결과물이 나오는 곳** | 채팅창 안 → 복사/다운로드해서 옮겨야 함 | **처음부터 내 폴더에 파일로** 생성 |
| **역할** | 답을 **알려주는** 도구 | 일을 **해주는** 도구 |

세 번째가 본질입니다. 첫 두 개는 이 세 번째를 가능하게 하는 조건일 뿐입니다.

**꼭 짚어야 할 보충 설명**

- 업로드 개수 제한은 플랜·시점에 따라 바뀝니다. 숫자를 외우기보다 **"업로드냐 폴더 연결이냐"** 라는 구조 차이로 기억하는 게 맞습니다. 폴더를 연결하면 파일 수를 세는 일 자체가 없어집니다.
- 코워크는 채팅보다 **사용량(usage)을 훨씬 많이 씁니다.** 아무 일에나 켜는 게 아니라 "결과물이 파일로 나와야 하는 일"에 켜는 도구입니다.
- 채팅의 메모리는 코워크로 넘어오지 않습니다 (같은 프로젝트 안이면 예외).

**새로 배울 개념 4개** — 이 슬라이드는 발표 내내 참조하게 되니 인쇄물로도 나눠주세요.

| 개념 | 한 줄 정의 | 언제 쓰나 |
|---|---|---|
| **폴더** | 코워크가 읽고 쓸 수 있게 연결한 내 컴퓨터 폴더 | 항상 |
| **프로젝트** | 폴더 + 지시사항 + 대화 이력을 묶어둔 작업 공간 | 같은 일을 **반복**할 때 |
| **스킬** | "이 절차로 해라"를 저장해둔 나만의 명령 | 절차가 **고정**됐을 때 |
| **스케줄** | 정해진 시간에 알아서 실행 | 내가 **없어도** 돌아야 할 때 |

> "폴더는 재료, 프로젝트는 주방, 스킬은 레시피, 스케줄은 타이머입니다."

### Part 3 (7분) — 시작 전 안전수칙 3가지

**이 파트를 절대 건너뛰지 마세요.** 코워크는 실제 파일을 지우고 옮기는 도구입니다. 안전수칙 없이 배포하면 사고가 납니다.

**① 전용 폴더를 만들고 거기서만 쓴다**

데스크톱 전체, 다운로드 폴더 전체를 통째로 연결하는 사람이 꼭 있습니다. 하지 마세요. `~/Desktop/코워크_작업실` 같은 전용 폴더를 만들고 작업할 파일만 넣습니다. 사고가 나도 피해가 그 폴더 안으로 제한됩니다.

**② 중요한 원본은 복사본으로 작업한다**

계약서, 회계 장부, 원천 데이터, 가족 사진. 원본에 바로 붙이지 않습니다. 복사본을 전용 폴더에 넣고 작업하고, 결과가 마음에 들면 그때 원본을 대체합니다.

**③ 승인 모드를 켜둔 채로 쓴다**

코워크는 작업 단계마다 물어봅니다. 설정에 "모든 승인 건너뛰기"가 있는데, 처음엔 귀찮아서 켜고 싶어집니다. **켜지 마세요.**

> "이 승인 요청이 불편한 기능이 아니라 **안전장치**입니다. AI가 다 알아서 하는 구조가 아니라, **계획은 AI가 세우고 결정은 내가 하는 구조**. 이게 있어야 코워크를 마음 놓고 씁니다."

승인 모드는 대체로 세 단계로 제공됩니다 (버전에 따라 명칭이 다를 수 있음).

- **수동(승인 요청)** — 모든 작업 전에 물어봄. **처음엔 이걸로.**
- **자동** — 읽기 작업은 자동 승인, 쓰기·삭제는 안전성 검토 후 진행
- **건너뛰기** — 아무것도 안 물어봄. 권장하지 않음

**④ (추가 권장) 프롬프트 끝에 항상 붙이는 한 줄**

```
원본 파일은 건드리지 말고, 실행하기 전에 어떻게 할지 계획만 먼저 알려줘. 내가 괜찮다고 하면 시작해 줘.
```

> "이 한 줄이 오늘 배우실 것 중에 제일 값어치가 큽니다. 저는 이걸 텍스트 대치(스니펫)로 등록해서 씁니다."

**보안 관련 필수 언급** (4월 교육 내용 연결)

- 클라우드 AI는 입력이 서버로 전송되는 구조입니다. 코워크는 **내 로컬 파일을 읽어서 보낸다**는 점에서 체감 위험이 더 큽니다.
- 회사 R&D 원천자료, 개인정보, 미공개 계약 조건은 **사내 정책을 먼저 확인**하고 쓰세요. 필요하면 이름·금액·식별자를 마스킹한 사본으로 작업합니다.
- 팀/엔터프라이즈 계정은 관리 정책과 감사 기능이 다릅니다. 개인 Pro로 회사 자료를 다루기 전에 반드시 승인 절차를 밟으세요.

## 4. 시연 스크립트

각 시연은 같은 리듬으로 갑니다. **① 무엇을 해결하나 → ② 폴더 연결 → ③ 프롬프트 붙여넣기 → ④ 계획 검토 → ⑤ 실행 → ⑥ 실제 폴더 열어서 확인 → ⑦ 그래서 뭐가 달라졌나**

⑥번을 꼭 하세요. **탐색기/파인더에서 실제 파일을 열어 보여주는 순간**이 청중이 납득하는 지점입니다.

### D1. 뒤죽박죽 폴더 정리 (8분)

**해결하는 문제**: 이름만 봐서는 뭔지 모르는 파일 수십 개. "나중에 정리하자"가 3년째.

**보여줄 코워크 기능**: 로컬 파일 접근 + 내용 기반 판단 + 파일 이동/이름 변경

**준비**
```bash
cp -R ~/Desktop/코워크_시연/01_폴더정리/원본 ~/Desktop/코워크_시연/01_폴더정리/사본
```
먼저 `사본` 폴더를 파인더로 열어 보여줍니다. `무제.txt`, `최종_진짜최종_v3.txt`, `asdf.txt`, `복사본의 복사본 (1).csv`… 청중이 웃으면 성공입니다.

**클릭 경로**
1. Claude 데스크톱 앱 → 왼쪽 사이드바 상단의 코워크 아이콘
2. 프로젝트 / 작업 → **폴더 선택** → `01_폴더정리/사본`
3. "Claude가 이 폴더의 파일을 변경할 수 있도록 허용" 팝업 → **허용**
4. 오른쪽 승인 옵션이 **승인 요청**으로 되어 있는지 확인 (여기서 안전수칙 ③을 다시 짚기)

**프롬프트**
```
이 폴더 안의 파일들을 정리해 줘.

1. 파일 이름만 보고 판단하지 말고, 파일 내용을 실제로 읽어서 무슨 문서인지 판단해 줘.
2. 아래 폴더로 분류해 줘:
   - 01_보고서
   - 02_회의_메모
   - 03_예산_정산
   - 04_규정_지침
   - 05_대외_협력
   - 99_삭제후보
3. 파일 이름은 `YYYYMMDD_내용요약.확장자` 형식으로 바꿔 줘. 날짜를 알 수 없으면 날짜 없이 내용 요약만 써 줘.
4. 내용이 비어 있는 파일은 99_삭제후보 폴더로 옮기기만 하고 절대 삭제하지 마.
5. 어떤 파일이 어떤 이름으로 어디로 갔는지 `정리내역.md` 파일로 기록해 줘.

원본 파일 내용은 수정하지 말고, 실행하기 전에 어떻게 할지 계획만 먼저 알려줘. 내가 괜찮다고 하면 시작해 줘.
```

**진행 포인트**
- 계획이 나오면 **소리 내어 읽으면서** "이걸 제가 검토하는 겁니다"를 강조
- 일부러 하나 고쳐보세요: `"03_예산_정산 말고 03_예산 으로 해 줘"` → 자연어로 수정되는 걸 보여줌
- "진행해 줘" → 완료 후 **파인더에서 폴더 열기**
- `정리내역.md` 를 열어서 "파일 수가 많을 때 이 기록이 검토 시간을 줄여줍니다"
- `99_삭제후보`를 열어서 **"삭제는 사람이 합니다"** 강조

**멘트**
> "여기서 중요한 건 폴더가 예뻐진 게 아닙니다. **파일 내용을 읽고 분류했다**는 겁니다. 이름이 `asdf.txt`인 파일이 대외 협력으로 갔죠. 이름만 봤으면 절대 못 합니다."

**플랜 B**: 계획 단계에서 이상한 분류가 나오면 그대로 보여주고 자연어로 고치세요. 오히려 좋은 교육 장면입니다. 완전히 실패하면 미리 정리해둔 결과 폴더 스크린샷으로 넘어갑니다.

### D2. 영수증 사진 → 경비 정산 엑셀 + 제출용 PDF (10분)

**해결하는 문제**: 영수증 사진 수십 장을 눈으로 보면서 엑셀에 타이핑하는 반나절.

**보여줄 코워크 기능**: 이미지·PDF 읽기(OCR) + 해석 + **새 파일 생성** + 판독 실패 시 정직하게 표시

**준비**
```bash
cp -R ~/Desktop/코워크_시연/02_영수증정산/영수증 ~/Desktop/코워크_시연/02_영수증정산/사본
```
`사본` 폴더를 열어 영수증 사진들을 보여줍니다. `IMG_2046.png` 는 **일부러 흐리게** 만든 파일입니다. 미리 말하지 마세요.

**클릭 경로**: 프로젝트 아이콘 → **다른 폴더 선택** → `02_영수증정산/사본`

> ⚠️ 여러 시연을 이어서 할 때 **이전 작업 폴더가 같이 선택된 채로 남아있지 않은지** 꼭 확인하세요. 코워크가 엉뚱한 폴더를 건드립니다.

**프롬프트**
```
이 폴더에 영수증 파일들이 있어. 사진(PNG)도 있고 PDF도 있어.

각 영수증에서 아래 항목을 읽어서 경비 정산용 엑셀 파일로 만들어 줘.
- 사용일자 / 사용처 / 사업자번호 / 내역 / 금액 / 결제수단 / 파일명

그리고 아래도 함께 처리해 줘.
1. 카테고리 열을 추가해서 식비 / 카페 / 교통 / 도서·자료 / 사무용품·다과 로 분류해 줘.
2. 카테고리별 소계와 전체 합계를 표로 만들어 줘.
3. 사진이 흐려서 못 읽는 항목은 비워두지 말고 "확인 필요" 라고 적고, 그 행은 눈에 띄게 표시해 줘.
4. 금액은 숫자 서식으로 넣어 줘.

원본 영수증 파일은 건드리지 말고, 실행하기 전에 계획만 먼저 알려줘. 내가 괜찮다고 하면 시작해 줘.
```

**진행 포인트**
- 실행 후 **엑셀 파일을 실제로 열어서** 프롬프트 항목을 하나씩 대조: 날짜 ✓ 사용처 ✓ 카테고리 ✓ 합계 ✓
- **"확인 필요" 행에서 반드시 멈추세요.** 이게 이 시연의 하이라이트입니다.

> "이게 제가 오늘 제일 강조하고 싶은 장면입니다. AI가 **모르는 걸 모른다고 적었습니다.** 4월 교육에서 배운 할루시네이션 기억하시죠? AI는 보통 그럴듯하게 지어냅니다. 그래서 프롬프트에 **'모르면 비워두지 말고 확인 필요라고 써라'** 를 명시적으로 넣어야 합니다. 이 한 줄이 검토 시간을 절반으로 줄입니다."

- 이어서 추가 요청 한 번 더 (후속 요청이 자연스럽게 된다는 걸 보여주기)

```
이 경비 보고서를 회사에 제출할 PDF 요약본으로도 만들어 줘. 표지에 정산 기간과 총액을 크게 넣고, 카테고리별 소계 표와 상세 내역을 순서대로 넣어 줘. 확인 필요 항목은 별도 섹션으로 빼 줘.
```

**멘트**
> "챗에서 이걸 하려면 사진 올리고, 표 받고, 복사해서 엑셀에 붙이고, 서식 맞추고, 다시 PDF로 만들었겠죠. 코워크는 **처음부터 제 폴더에 엑셀과 PDF가 놓입니다.** 옮기는 과정이 아예 없어요."

**플랜 B**: OCR이 몇 개 실패하면 그것도 그대로 보여주세요. "이래서 사람이 검토합니다"가 오늘의 메시지와 정확히 맞습니다.

### D3. 회의록 7개 → 액션아이템 + 담당자별 메일 초안 + 주간 요약 (10분)

**해결하는 문제**: 회의록은 쌓여 있는데 "그래서 내가 뭘 해야 하지"가 정리되지 않음. 팔로업 메일 쓰기 귀찮아서 미룸.

**보여줄 코워크 기능**: 여러 파일 교차 참조 + **한 번의 요청으로 여러 종류의 결과물 동시 생성** + 병렬 처리

**준비**
```bash
cp -R ~/Desktop/코워크_시연/03_회의록/원본 ~/Desktop/코워크_시연/03_회의록/사본
```
회의록 7개를 열어 보여줍니다. 담당자가 겹치고 기한이 흩어져 있는 걸 짚어주세요.

**프롬프트**
```
이 폴더에 지난 2주간의 회의록 7개가 있어. 아래 3가지를 만들어 줘. 서로 독립적인 작업이니까 동시에 진행해 줘.

1. `액션아이템.xlsx`
   - 열: 담당자 / 할 일 / 기한 / 출처회의 / 상태 / 지연위험
   - 모든 회의록에서 할 일을 빠짐없이 뽑아 줘.
   - 기한이 빠른 순으로 정렬하고, 오늘(2026-08-12) 기준으로 이미 지난 기한은 지연위험 열에 "기한 경과"로 표시해 줘.
   - 같은 사람에게 같은 주에 3건 이상 몰려 있으면 "업무 집중"으로 표시해 줘.

2. `팔로업메일/` 폴더 안에 담당자별 메일 초안을 각각 파일로 만들어 줘.
   - 파일명은 `메일_담당자명.md`
   - 그 사람 할 일만 모아서, 기한과 출처 회의를 함께 적어 줘.
   - 정중하지만 짧게. 300자 이내.

3. `주간요약.md`
   - 이번 2주간 무슨 일이 있었는지 한 눈에 볼 수 있게.
   - 결정된 사항 / 아직 결정 안 된 사항 / 기한이 급한 것 / 여러 회의에 반복 등장한 이슈 로 나눠 줘.

실행하기 전에 계획만 먼저 알려줘.
```

**진행 포인트**
- **"동시에 진행해 줘"** 를 짚어주세요. 서로 영향 없는 작업은 병렬로 돌려 시간을 줄일 수 있습니다.
- 결과 확인 순서: **주간요약 → 메일 초안 → 엑셀**. 사람이 읽는 순서대로.
- `주간요약.md` 의 **"여러 회의에 반복 등장한 이슈"** 를 짚으세요. 7개 회의록을 한 번에 봐야만 나오는 결과입니다. (P-102 원료 수급이 3개 회의에 걸쳐 등장)
- 메일 초안 하나를 열어서: "이걸 그대로 보내라는 게 아닙니다. **빈 화면에서 시작하지 않게 해주는 것**이 핵심입니다."

**멘트**
> "여기서 코워크가 한 일은 요약이 아닙니다. **회의록 7개를 가로질러 본 것**입니다. 사람도 할 수 있지만, 7개를 다 펼쳐놓고 담당자별로 재배열하려면 한 시간 걸리죠."

**플랜 B**: 병렬 처리가 잘 안 보이면 넘어가세요. 결과물 3종이 나온 것 자체가 메시지입니다.

### D4. 리서치 소스 10개 → 소스 평가표 + 비교 분석 (10분)

연구소 리서치 담당에게 **가장 직접적으로 꽂히는 시연**입니다. 60분 버전에서도 이건 넣으세요.

**해결하는 문제**: 자료를 10개 20개 모아놓고 어디까지 믿을 수 있는지 판단이 안 됨. 결국 눈에 익은 것만 인용.

**보여줄 코워크 기능**: 다수 문서 비판적 검토 + 신뢰도 등급화 + 상충하는 주장 찾아내기

**연결 포인트**: 4월 교육의 NotebookLM 소스 평가표를 코워크에서 하는 것입니다. "넣은 소스의 성격부터 먼저 파악하는 습관" 그대로입니다.

**준비**
```bash
cp -R ~/Desktop/코워크_시연/04_리서치소스/소스 ~/Desktop/코워크_시연/04_리서치소스/사본
```

**프롬프트 (1단계 — 소스 평가표)**
```
이 폴더에 리서치용 소스 10개가 있어. 본문을 읽기 전에 먼저 소스의 성격부터 평가하고 싶어.

`소스평가표.xlsx` 를 만들어 줘. 열은 아래와 같이.
- 소스명 / 핵심요약(100자 이내) / 발행일 / 발행주체 / 소스구분(학술논문·정부자료·시장보고서·뉴스·기업자료·블로그·커뮤니티) / 신뢰도(5점) / 참고가치(10점) / 신뢰도 근거 / 주의사항

평가 기준:
- 신뢰도는 발행주체의 검증 수준으로 판단해 줘. 피어리뷰·정부 통계는 높게, 익명 커뮤니티·자사 홍보성 글은 낮게.
- 참고가치는 우리가 '기능성 소재 분야 사업 기회'를 검토한다는 목적에 얼마나 도움되는지로 판단해 줘. 신뢰도와 별개로 매겨 줘.
- 주의사항에는 "IR 자료라 낙관 편향", "정량 근거 없음", "실험실 규모 결과" 처럼 인용할 때 조심할 점을 적어 줘.

신뢰도 높은 순으로 정렬해 줘. 실행 전 계획만 먼저 알려줘.
```

**프롬프트 (2단계 — 비교 분석 보고서)**
```
이제 소스평가표를 참고해서 `사전검토_메모.md` 를 써 줘.

1. 소스들이 공통으로 말하는 것 (합의된 사실)
2. 소스끼리 서로 다르게 말하는 것 — 어느 소스가 뭐라고 했는지 반드시 함께 적어 줘
3. 아무 소스도 답해주지 않는, 우리가 따로 확인해야 할 질문 5개
4. 신뢰도 3점 이하 소스에서만 나온 주장 — 이건 근거가 약하다고 따로 표시
5. 마지막에 "이 자료들만으로는 결론 낼 수 없는 것" 을 솔직하게 적어 줘

각 문장에 근거가 된 소스 파일명을 괄호로 표기해 줘. 없는 내용은 절대 만들어내지 마.
```

**진행 포인트 — 이 시연의 핵심은 3번과 5번입니다**
- 2번 "서로 다르게 말하는 것": 원료 수급 상황이 커뮤니티 글과 다른 소스에서 다르게 나옵니다.
- 5번 **"결론 낼 수 없는 것"**: 이걸 짚으면서 4월 교육 메시지를 회수합니다.

> "AI에게 **모른다고 말할 자리를 만들어주는 것**이 프롬프트 기술의 거의 전부입니다. '결론 내줘'라고만 하면 반드시 결론을 냅니다. 근거가 없어도 냅니다. '결론 낼 수 없는 건 솔직히 적어줘'를 넣으면 훨씬 쓸 만한 문서가 나옵니다."

### D5. 반복 업무를 '스킬'로 굳히기 (8분) — *90분 버전*

### 5-2. 한계와 주의사항 (솔직하게)

- **사용량을 많이 씁니다.** 채팅보다 훨씬 빨리 한도에 닿습니다. 아무 일에나 켜지 마세요.
- **검토 시간은 줄지 않습니다.** 오히려 늘 수도 있습니다. 줄어드는 건 **만드는 시간**입니다.
- **틀린 결과가 파일로 조용히 저장됩니다.** 채팅은 눈앞에서 읽고 넘어가지만 파일은 안 읽고 제출할 수 있습니다.
- **보안**: 회사 자료를 쓰기 전 사내 정책 확인. 원천 데이터·개인정보·미공개 계약은 마스킹 사본으로.
- **완전 자동화는 목표가 아닙니다.** 사람이 판단할 지점은 남겨두세요 (승인 모드를 켜두는 이유).

### 5-3. 30일 실천 플랜 (배포용)

발표 마지막 슬라이드이자 인쇄해서 나눠줄 내용입니다. 이것만 남아도 성공입니다.

| 주차 | 할 일 | 성공 기준 |
|---|---|---|
| **1주차** | 데스크톱 앱 설치. `코워크_작업실` 전용 폴더 만들기. **D1(폴더 정리)을 내 파일로** 한 번 해보기 | 승인 요청 모드에서 계획을 읽고 승인해봤다 |
| **2주차** | 내 업무 중 **매주 반복하는 일 1개**를 골라 코워크로 해보기 (경비 정산 / 회의록 정리 / 자료 요약 중 하나) | 결과물 파일이 내 폴더에 생겼다 |
| **3주차** | 그 일을 **프로젝트로 만들고 스타일/기준 파일을 참고 폴더에 넣기** | 두 번째부터 설명이 짧아졌다 |
| **4주차** | 그 절차를 **스킬로 저장**. 여유 있으면 스케줄 1개 등록 | 한마디로 실행된다 |

## 6. 예상 질문 (FAQ)

**Q. 무료로 쓸 수 있나요?**
아니요. Pro / Max / Team / Enterprise 유료 플랜에서만 됩니다. 로컬 파일을 다루려면 데스크톱 앱도 필요합니다.

**Q. 제 컴퓨터 파일이 전부 클로드에 올라가는 건가요?**
연결한 폴더 안의 파일만 접근합니다. 다만 접근한 내용은 처리를 위해 서버로 전송되는 구조입니다. 그래서 전용 폴더만 연결하고, 민감 자료는 넣지 않는 게 원칙입니다.

**Q. 파일을 잘못 지우면 어떻게 되나요?**
그래서 ① 전용 폴더 ② 복사본 작업 ③ 승인 요청 모드 3개가 있습니다. 3개를 다 지키면 사고가 나도 사본 폴더 안에서 끝납니다. 삭제가 걱정되면 프롬프트에 `삭제하지 말고 99_삭제후보 폴더로 옮기기만 해` 를 넣으세요.

**Q. 챗GPT나 Gemini로도 되나요?**
비슷한 방향의 기능들이 계속 나옵니다. 4월 교육 결론대로 도구 비교에 시간 쓰는 것보다 **한 개를 골라 내 업무에 붙이는 게** 낫습니다. 로컬 파일을 직접 다루는 경험은 현재 코워크가 정리가 잘 된 편입니다.

**Q. 엑셀 함수를 몰라도 되나요?**
결과물에 값이 아니라 **수식**이 들어가서, 데이터가 바뀌면 자동 반영됩니다. 다만 수식이 맞는지 검토할 수 있어야 합니다. 4월 교육 표현대로 **"엑셀은 공부해서 배우는 도구가 아니라 시키는 도구"** 가 됐지만, 결과를 판단하는 능력은 여전히 필요합니다.

**Q. 그래서 우리 일자리는요?**
4월 교육 결론과 같습니다. 활용 능력은 진입장벽이 거의 없어서 경쟁력이 되기 어렵습니다. 남는 건 **도메인 지식과 판단력**입니다. 코워크가 만든 경비 정산표가 규정에 맞는지, 리서치 요약이 인용해도 되는 수준인지 아는 사람이 필요합니다. 그 판단은 오늘 배운 도구가 못 합니다.
